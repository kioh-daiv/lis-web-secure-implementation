# 部門システム Web 基盤 セキュア実装ガイド — どこまでやれば安心か

臨床検査部門システム（LIS）の Web サービスを、法規制・安全要件を満たして実装するためのガイド。「医療DX シリーズ」第 4 部。工程表（全体像）→ 法規制対応（AWS 基盤）→ 受注の資格要件、に続き、本ガイドは**アプリ／Web 基盤層の実装**を扱う。

## 設計：2 つの問いに分ける

- **何を実装するか**：機能ロジックの「上」に、認証・認可・監査ログ・データ保護・Web セキュリティを組み込む。AWS（インフラ）が用意した暗号化基盤・WAF・監査基盤を、アプリが正しく使う実装。
- **どこまでやれば安心か**：「安心」を主観で語ると終わらないので、**OWASP ASVS 5.0 のレベル2（L1+L2）を安心ライン**に置く。これに 3省2ガイドラインのアプリ要件と検査業務特有を上乗せした状態を「客観的にここまでやった」と定義する。

## 構成（6 タブ）

- **安心ラインの考え方**：ASVS の L1/L2/L3、L2 が安心ライン、過剰と不足の線引き、カテゴリ一覧
- **認証・セッション・認可**（ASVS V6/V7/V8）：二要素認証、セッションタイムアウト、RBAC、データ単位認可（IDOR 対策）
- **入力・出力・Web**（V1/V2/V3/V4）：入力検証、SQLi/XSS/CSRF/SSRF
- **暗号・データ保護・通信**（V11/V12/V14）：フィールド暗号化、マスキング、鍵管理、TLS 強制
- **ログ・API・設定・依存**（V13/V15/V16）：監査ログ、エラー処理、API 認証、依存脆弱性管理、秘密情報
- **検査業務特有**：精度管理記録、トレーサビリティ、結果確定・訂正履歴、パニック値・感染症届出連携

各項目に「なぜ（法規制根拠）／ Spring・Angular 実装例 ／ レベル（L1/L2/L3）」を付け、現場が「何を・どこまで」を一目で判断できる形にした。

## 実装スタック

Java(Spring Security 6)＋Angular を想定（LIMS の実スタック）。実装例は方針を示すコード断片で、採用バージョンの公式ドキュメントで最新の作法を確認すること。

## 注意

2026 年 5 月時点の一般整理。OWASP ASVS は 5.0.0（2025年5月）を参照。ASVS のレベルは目安で、最終的な実装範囲は対象システムのリスク評価に基づく。実装例の正確性は採用環境で検証すること。法規制の条項は原典で最終確認すること。
